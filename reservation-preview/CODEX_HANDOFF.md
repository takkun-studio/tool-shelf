## 最優先の確定要件
この節が最優先。後続の監査記録・過去案・過去調査と矛盾する場合は、この節を採用する。

- このアプリの利用者は各自のGoogleアカウントを接続して使う
- Google Cloud project / Calendar API / OAuth client の用意・設定はアプリ運営側の仕事であり、エンドユーザーには要求しない
- エンドユーザーが行うのは、アプリ上でGoogleにログインし、必要なCalendar権限へ同意することだけ
- 接続後は、その利用者本人がアクセスできるGoogle Calendar一覧を取得する
- 利用者は、予約の登録・照合に使うCalendarと、私用・仕事・講座・祝日等の予定参照に使うCalendarを自分で選べる
- 予定参照Calendarは複数選択可能にし、そこに入っている予定は月間・日別表示と予約可能時間の判定に反映する
- 予約Calendarだけ見て、本人の他予定を無視する設計は禁止
- 開発者個人のCalendar名・ID・予定内容を本番仕様へハードコードしない
- Google Calendarへの書き込み・変更・削除は、利用者確認なしに自動実行しない
- 外部調査、料金確認、API仕様確認、OAuth条件確認、サービス比較、構成選定はChatGPT側で行う
- Codexは実装担当。外部Web調査、管理画面調査、料金調査、サービス選定、OAuth/Cloudflare設定変更を独自に行わない
- Codexが外部情報を必要とした場合は推測せず、不足事項として報告して止める
- バックエンド、DB、Worker、OCR方式、OAuth方式、料金条件は、ChatGPTから明示的な確定実装指示が来るまで未確定として扱う
- main、本番、既存HP、既存DB、課金設定、外部サービス設定を勝手に変更しない

### 機能（今回）
- 写真登録画面（スマホ下部タブ「写真登録」）：①写真を撮る・選ぶ → ②文字を読み取る → ③候補の確認・修正 → ④最終確認 → 登録
- OCR結果は自動登録しない。最終確認の「この内容で登録」だけが保存する。登録型は「手書き台帳の予約」（`source: 'photo-ocr'`）。Googleへは書き込まない
- 推測しない：存在しない日付・25時などは空欄＋理由、午前/午後不明（「6時」）は空欄（営業時間を設定するとその範囲で判定）、人数の記載なし・複数記載は空欄、「様」がない名前は要確認、曜日の食い違いは要確認、確信度の低い行は要確認
- 重複：登録済み台帳と同じ日付・開始・お名前は登録不可（同じ取込内の重複も不可）。カレンダー側の同じ予約は「照合で一致扱い」と表示。同日同名・個人予定との重なり・予約上限超過は警告
- 失敗時の保持：作業中の写真（バイト列）・読み取り文字・修正中の候補を IndexedDB に一時保存し、再読み込みで復元。OCRの読み込み失敗は「もう一度読み取る」で回復、手入力で候補を作ることも可能。保存失敗時も候補を保持。登録後に一時保存は消去
- 懐石料理店向け：人数（`guests`、任意・1〜999の整数）を追加。旧データ（人数なし）はそのまま読める。美容室のサンプル・文言（カット・カラー等）は削除
- 店舗の設定（`schedule-settings-v1`）：営業時間・標準の利用時間・同じ時間帯の予約上限。すべて空欄が初期値（店舗情報を決め打ちしない）。営業時間未設定時は空き時間を「未設定」と表示。終了時刻のない台帳行は仮に120分後（要確認表示、設定で変更可）
- 照合の変更点：予約同士の時間の重なりは「予約上限」を設定した場合だけ警告（同時刻に複数組を受けるため）。個人予定との重なりは従来どおり警告。「台帳にだけある予約」はカレンダー側の予約を使っている場合だけ警告。月間カレンダー・タイムラインに「台帳のみ」の予約も表示
